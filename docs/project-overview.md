# my-agent：项目介绍草案

日期：2026-10-12；状态：第一天范围定义，尚未表示功能实现。

## 一句话定义
my-agent 面向企业研发人员和技术负责人：用户提供知识库需求、架构材料和 2–3 个候选检索方案，系统基于可追溯证据比较候选，输出条件性建议、未知项和验证计划。

## 用户问题
需求与候选资料分散，版本和部署方式不同。仅靠模型记忆容易忽略硬约束、把缺资料当成不支持，或把宣传说成性能实测。
项目把“理解需求—计划—取证—缺口检查—有限补查—比较—核验—报告”组织为可观察、可复核的流程。

## 输入和输出
输入：文本 PDF/MD/TXT、2–3 个候选及版本/部署模式、硬约束、偏好、允许的资料来源与研究模式。
输出：需求摘要、候选×维度矩阵、判断依据、推荐与替代方案、未知/冲突项、验证计划；重要结论可定位到原文。

## 开发与验证
独立实现业务，不以导入 GPTResearcher 代替自己的 Agent 核心。后端 Python/FastAPI，前端 TypeScript/Next.js，Docker Compose 部署。
第一周先完成工程、模型能力验证和项目权限；文档入库、检索与 Agent 循环按既有八周指南逐步实现。
