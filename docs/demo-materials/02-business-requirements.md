# D02：业务需求与硬约束

资料性质：**合成测试材料**；候选为虚构方案，不对应真实产品。  
文档修订：demo-r1；编写日期：2026-10-12。  
状态：第一天测试夹具，未执行部署或性能实验。

## 硬约束
- H01：候选的检索服务与索引数据必须能够在企业控制的 Linux 环境私有部署；仅提供厂商托管服务不能满足。
- H02：查询必须限定在服务端授权的项目和有效文档版本内。候选需要提供可用的过滤接口，应用必须强制注入范围；客户端不能取消过滤。过滤能力不等于完整身份认证。
- H03：支持稳定片段 ID 的幂等新增/更新，以及删除指定片段；删除完成后不能继续把这些片段作为有效证据。程序负责版本发布和残留索引隔离。
- H04：报告中的关键能力判断保留来源 ID、候选版本、适用部署模式与原文位置。引用记录由 my-agent 实现，不能因候选缺少报告功能就判定候选不合格。

## 软偏好
优先易于由一名 Python 开发者维护、适合 Docker 部署、有清楚接口的方案。中文检索效果、耗时与成本要通过统一数据验证。
用户尚未确认各维度的评分权重，禁止生成综合分或百分比置信度。

## 范围与未知项
文本 PDF/MD/TXT 为第一版输入。扫描件 OCR、SSO、自动采购与自动性能实验不在第一版。
D04 提供的是场景假设和验收目标，不是实测数据；真实企业数据规模、预算与并发需求仍需用户确认。
