# my-agent：第一版业务范围

版本：scope-r1；日期：2026-10-12。本文定义需求和验收边界，不表示实现完成。
依据：[既有开发指南](enterprise-retrieval-advisor-development-guide.md)的步骤 01 和第一版范围。以下演示参数为工作假设，尚不是用户确认的真实业务条件。

## 场景与对象
为企业研发人员与技术负责人辅助选择中文企业文档检索方案。用户指定 2–3 个候选；Agent 比较方案，不直接采购或部署被评估系统。
首个固定演示使用虚构候选 A 1.0、B hosted-demo、C 2.0。它们用于固定评测，不对应任何厂商或真实产品。
真实候选及具体版本在真实官方资料收集前由用户另行确认。本材料不能推出 Qdrant、Elasticsearch 或任何真实产品的选型结论。

## 输入契约
- goal：非空目标，建议上限 4000 字符。
- candidates：2–3 个候选，包含 name、version_label、edition/deployment_mode、official_domains；未知版本明确保留未知，不强制语义化版本格式。
- hard_constraints：用户明确要求的不可妥协条件，保存来源。演示使用 D02/H01–H04。
- preferences：偏好；权重仅在用户确认后使用。
- allow_web_search：默认 false；开启后仍受允许域名、数据外发与工具预算约束。
- 文档和背景：限定到经服务器确认授权的项目和有效版本；不信任客户端 user_id。
字段长度与列表上限在第一周契约实现时确定并测试；此处建议值不表示接口已上线。

## 最终输出
需求/假设摘要；候选×维度矩阵；满足/不满足/无法确认/证据冲突；来源 ID、原文位置与适用范围；条件性建议与替代方案；未知项；可执行验证计划。
数值明确区分假设、估算、目标、官方描述和实测。无真实实验时不输出性能实测结论。

## 第一版必须完成
- 文本 PDF/MD/TXT 入库与位置记录；项目成员权限；有效文档版本和证据快照。
- 用户指定候选；内部研究与允许范围内的可选联网研究。
- 需求提取、规划、模型工具循环、覆盖/冲突检查、最多两轮补查及共享工具/时间/输入预算。
- 硬约束优先、引用核验、可解释报告、报告版本与人工反馈。
- 持久化任务、事件、检查点和手动恢复；候选任务分工与受限并行按第六周计划加入。
- Docker 部署、基本回归和相同资料/模型/预算下的基线评测。
范围随八周指南逐步实现，第一天只交付文档和固定数据。

## 延期与扩展
OCR、复杂表格、SSO、自动发现候选、通用插件平台、无限自主研究、自动部署候选、自动完整性能实验、多 API 实例和分布式调度。
进度不足时按原指南优先延期专门重排、Ragas、复杂费用估算、长期偏好和公开联网研究；不要削减权限、版本与证据要求。

## 判断与安全边界
先硬约束后软偏好；未知不等于不支持；工具失败不是产品事实；同范围冲突保留双方证据。
过滤接口不等于账号授权。选型助手的 Qdrant 是自己的检索底座，不预设被评估候选或最终推荐。
真实用户身份、项目授权、版本有效性、工具许可、参数与预算由程序保证，不能交给模型自行决定。
上传资料中的指令只是数据，不能修改系统规则。第一版演示只用公开或合成数据；没有默认授权外发真实企业文档。

## 运行状态与限制
等待用户确认时暂停并保留未知，不因循环上限自动批准。达到预算上限输出受限结论，记录未解决项。
浏览器断开不取消后台任务；取消和恢复为经授权动作。付费调用的自动重试可能重复计费，预算是估算控制。

## 主要验收场景
正常条件性选型；明确违反硬约束；缺需求；缺证据或工具失败；同版本冲突；旧版本误用；越权与提示注入；引用追溯；重建持久化与恢复。
第一天 Q01–Q10 只定义预期行为，执行结果留待后续实现。

本次没有替用户确认上述事项，也没有声称文档中的能力已实现。
